# VYNET | فاينت

منصة المالك/الإدارة والوكيل لإدارة الشبكات والبطاقات والعهدة والتحويلات. تطبيق العملاء المستقل لاحقًا هو VY CARD. المستودع يحتوي على واجهات عربية RTL، منطق مجال، اختبارات وحدات، ومخططات Supabase. **ليس MVP تشغيليًا بعد**: لم يثبت وجود بيئة Supabase أو تطبيق migrations.

## المتطلبات والتشغيل

- Node.js 20.9 أو أحدث؛ جرى الفحص على Node.js 24.19.0.
- pnpm 11.19.0؛ استخدم `pnpm` فقط.

```bash
pnpm install --frozen-lockfile
pnpm dev
```

أوامر الجودة:

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

## البنية

```text
src/app/                 صفحات App Router وServer Actions
src/components/          عناصر الواجهة المشتركة
src/config/              تعريفات العرض والمسارات
src/lib/domain/          قواعد مجال نقية
src/lib/imports/         تحليل CSV وتصنيف الصفوف
src/lib/security/        تشفير بيانات البطاقة وبصمتها
src/lib/supabase/        عميل Supabase خادمي وإعداداته
src/types/               أنواع المجال
supabase/migrations/     مخطط PostgreSQL وسياسات RLS وRPCs
tests/                   اختبارات وحدات محلية
docs/                    المعمارية والنطاق والأمن والقرارات والتشغيل
```

توضح الصفحات غير المكتملة حالتها ولا تدعي وجود بيانات حقيقية. المسارات `/login` و`/register` تستخدم Server Actions عند توفر إعدادات Supabase. تسجيل الدخول يوجه حساب المالك/الإدارة إلى مساحة الإدارة والوكيل إلى مساحة الوكيل، دون اختيار دور يدوي. استيراد CSV لديه Server Action أولية للتحقق من المستخدم والعضوية ثم حساب HMAC والتشفير بالخادم؛ لا توجد واجهة مراجعة واعتماد متكاملة. بقية واجهات العمليات لا تزال غير مكتملة.

## Supabase

انسخ `.env.example` محليًا إلى `.env.local` وضع القيم من مشروع **تطوير/اختبار** معتمد. المتغيرات السرية المطلوبة لتخزين البطاقات هي `CARD_ENCRYPTION_KEY` و`CARD_FINGERPRINT_KEY` (32 بايت لكل منهما، Base64). مسار الاستيراد يحتاج أيضًا `SUPABASE_SERVICE_ROLE_KEY` على الخادم فقط؛ لا تضعه في `NEXT_PUBLIC_*` ولا في المتصفح أو Git.

تسجيل الدخول للمستخدم برقم الهاتف وكلمة المرور دون عرض معرّف Auth الداخلي، المشتق بصيغة `phone@vynet.app`. التسجيل العام معطل؛ إنشاء العضويات يتم عبر مسارات إدارية فقط. تهيئة أول Owner متاحة كـRPC لمرة واحدة لا ينفذها إلا `service_role`، ولا توجد بيانات مستخدم أو منظمة مضمنة في المصدر.

توجد migrations في `supabase/migrations/` لكنها لم تُطبّق أو تُختبر على PostgreSQL/Supabase. يلزم بيئة اختبار معتمدة واختبارات RLS قبل اعتبارها صالحة للنشر. التحويلات المعلقة تنتهي بعد 24 ساعة؛ يمكن لمالك/مدير المنظمة تشغيل RPC التسوية، وهي تقفل السجلات وتحرر الحجز وتسجل ledger/audit دون حذف.

## حدود النسخة الحالية

- منجز محليًا: تحقق رقم الهاتف وmapping داخلي بصيغة VYNET، منع التسجيل العام لـCUSTOMER، تشفير AES-256-GCM، HMAC للتكرار، محلل CSV أولي، اختيار FIFO وقواعد انتقال نقية.
- جزئي: واجهات الحساب ومساحات الأدوار؛ migrations طلب/مراجعة/تنفيذ/قبول التحويل والتسعير والسجل المالي والتنبيهات غير مطبقة أو متحققة؛ لا توجد واجهة تشغيل متكاملة، واتصال Supabase غير مهيأ.
- مؤجل/محجوب: تشغيل الشبكات والمنتجات والدفعات والمخزون والتحويل والبيع والتسليم وتطبيق VY CARD والتدقيق والتقارير.

راجع `docs/mvp-scope.md` و`docs/decisions.md` للحالة التفصيلية.
